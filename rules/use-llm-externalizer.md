# Use LLM Externalizer (CLI)

Applies when: `llm-ext --help` succeeds (if it fails, this plugin isn't installed here — ignore this file). There is no MCP server for it: `mcp__…llm-externalizer…__*` tools do not exist — the CLI is the only surface.

`llm-ext <group> <action> [input] [-o dir] [--profile name] [--flag v]` covers 7 groups — `session llm scan check scout models settings` — over 50 commands, including the four text tools `llm summarize|topics|sem-deduplicate|describe` (size-bounded summary, keyword/keyphrase and language extraction, semantic phrase dedup, concise file characterization). Help nests: `llm-ext --help` → `<group> --help` → `<group> <action> --help`; a typo suggests the right verb and exits non-zero. Examples: `llm-ext session compact <session>.jsonl -o /tmp`, `llm-ext llm ask ./src/api.ts -o ./out --instructions "explain this file"` (`llm ask` needs `--instructions` or `--instructions_files_paths`), `llm-ext scan folder ./src`.

Prefer it over a Haiku subagent, or any subagent, for bounded read-only work — analyzing, summarizing, or scanning 3+ files, a big log, or wanting a second opinion. It's more capable and cheaper, and file contents never enter the caller's context: it prints a report path to read instead. It examines code and never edits it, so it isn't a fit for surgical edits or multi-step tool work.

`-o`/`--output` is shorthand for that command's `--output_dir`. Left out, reports go to `<project-root>/reports/llm-externalizer/<sub>/`, anchored on `$CLAUDE_PROJECT_DIR` — never a git root, because a linked worktree is ephemeral and reports written there are lost with it. Profile precedence is `--profile <name>` > `active: <name>` in settings.yaml > the built-in `free` profile; a fresh install writes `active: free`. A name picks a built-in profile (`free`, `paid`, `local`) or one listed under `profiles:` in `~/.llm-externalizer/settings.yaml` (that's `.yaml`; a legacy `settings.yml` is preserved on disk but not read). Once a command starts, it sticks to the selected profile for its whole run — on a model failure it falls back only to the next model of the SAME profile, never to another profile.

Every llm-ext env var uses the `LLM_EXT_` prefix — `LLM_EXT_OUTPUT_DIR` overrides the report-root default above, `LLM_EXT_CONFIG_DIR` overrides the settings directory.

A few operating rules: pass file paths, never file contents; include a line or two of project context, since the remote model knows nothing about the repo; for a question spanning the whole codebase use `scan impl`; give `scout *`, `scan security`, and `scan quality` a 20-minute timeout, or run them in the background.

`--command_timeout <s>` (aliases `--command-timeout`, `--timeout`) is accepted by every command, and any command still running when it expires exits 124: a command that sends model requests starts no new one, its queued local jobs are cancelled, the finished results are written and the command reports what it did not finish. Any command still running 30 s after the timeout is killed (exit 124), which is how a command that sends no model requests ends. `--queue_timeout <s>` is the longest a local job waits for its model server before a rotation is forced (default 300; never an error).

The built-in local profiles `local_llama` (GGUF, llama.cpp) and `locals-mlx` (MLX, macOS on Apple silicon) run models on this machine through a server llm-ext manages, and hold a model's requests until it is calibrated, which happens once, on its first use or when a model id changes in a used profile (or by hand with `llm-ext models calibrate --model <id>`), and can take hours (`llm-ext models calibration-status` shows progress).

On cost: on a paid profile, run the command with `--estimate` first and proceed only if the `ceiling` fits. The built-in `free` and `paid` profiles keep re-checking availability and price on every run and stay usable at $0; a profile you configured yourself and forced to free mode, with no free models of its own, refuses on a 402 instead of silently borrowing one — a wallet at zero is a reason to switch `--profile`, never a reason to skip the tool or do the work by hand instead. A returned report path means the call worked.
