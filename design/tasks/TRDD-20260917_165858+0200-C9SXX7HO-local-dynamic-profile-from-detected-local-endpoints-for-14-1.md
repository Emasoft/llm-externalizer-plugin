## Rule

local joins free and paid as the third built-in DYNAMIC profile: generated by llm-ext, marked # <-- do not touch, generated by llm-ext -->, hand edits regenerated, reserved name refused for static profiles.
Its content is derived from local_discovery/scan.ts (discoverLocalLlmServices -> buildProfileForService): the detected llama.cpp / OpenAI-compatible / LM Studio / Ollama endpoints and their served models.
It is regenerated when the detected endpoint set or their model lists change (an endpoint fingerprint of the same shape as dynamic-maintainer.ts poolFingerprint/modelSpecFingerprints at 493-582), checked on every llm-ext call like free/paid.
When nothing is detected the section is written unpopulated with PLACEHOLDER_MODEL_ID and selecting it refuses with a message naming the population state (never the sentinel id, fix-queue 83).
No paid spend, no network beyond localhost probes.
COORDINATOR DEFAULT (USER may override): model: = the first detected endpoint in PROBE_TARGETS order that serves at least one model, and that endpoint's first listed model; api: = the matching *-local preset (buildProfileForService already does this). coordinator defaults, in force until the USER overrides; D1 (5cab113) is built on them.

## Acceptance

On a machine with Ollama running, a fresh install's settings.yaml contains a marked local: section whose model: is a served Ollama model and whose api: is ollama-local; stopping Ollama and running any command regenerates the section (unpopulated or the next endpoint).
On a machine with no local runner the section is present, marked, unpopulated; --profile local refuses naming the population state.
A hand-authored local: static profile is refused with the reserved-name error.
All three names round-trip through settings status, the migration table in pick.ts, and --populate-default-profile validation.
