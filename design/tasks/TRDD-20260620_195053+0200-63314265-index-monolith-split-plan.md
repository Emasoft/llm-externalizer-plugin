## ⏵ STATE — READ THIS FIRST ON RESUME (authoritative) — 2026-06-20

- **What this is:** the phased extraction PLAN for splitting `mcp-server/src/index.ts`
  (8457 lines as of 2026-06-20; the TRDD-828238b5 "9599" figure is STALE — the A6
  search-existing extraction already shrank it). B1 is the last structural item in
  the 828238b5 backlog; A6 (free-form benchmarks) is BLOCKED on Phase 3 below.
- **Why a PLAN and not a done refactor:** a deep investigation (2026-06-20)
  established that index.ts has NO clean, co-located, low-coupling block for a
  quick safe extraction — every candidate is either (a) tiny + scattered + interleaved
  with impure module state, or (b) a large block heavily coupled to shared
  module-level state (the rate limiter, backend config, fetch helpers, the
  auto-free flags, the catalog cache). The global directives mandate phased
  execution with verification (and approval gates) for a multi-file refactor of
  SHIPPED code; rushing entangled extractions overnight on v10.0.0 risks breaking
  the server for modularity gains. So the deliverable now is this plan.
- **NEXT ACTION:** execute **Phase 1** (below) — the lowest-risk extraction — then
  run the full guard (build + 1133 vitest + lint) and STOP for review before Phase 2
  (per the phased-execution directive). Each phase ≤5 files, verify after each.
- **Load-bearing facts/gotchas:**
  - `index.ts` runs `main()` on import — any extraction must NOT change that, and a
    benchmark/runner importing an extracted core must avoid pulling `main()`.
  - The 1133-test TS suite + `doc-consistency` gate is the regression guard.
  - `dist/` is tracked → every phase must `npm run build` and commit the rebuilt
    bundle alongside the source.
  - When MOVING a symbol out and importing it back, index.ts internal call sites
    resolve to the imported binding automatically — but ALL OTHER importers
    (`grep -rl "<sym>" --include=*.ts | grep -v index.ts`) and test files must be
    updated, and the moved module must NOT import back from index.ts (circular).
  - NO backward-compat re-export shims (project rule) — update importers instead.

## Phase plan (each phase: ≤5 files, build+test+lint after, commit, then review)

- **Phase 1 — pure leaves (lowest risk).** Extract the genuinely-pure helpers to
  `request-overrides.ts` (`MODEL_REQUEST_OVERRIDES` + `applyModelOverrides`, 354-407)
  and `auto-free.ts` (the 4 pure helpers `parseFreeBelowUsd`, `resolveFreeModelId`,
  `resolveAutoFreePool`, `resolveSubsystemFreeModel`; LEAVE `selectFreeEnsembleModels`
  + `FREE_FLOOR_MIN_CONTEXT_TOKENS` for Phase 4 — they sit at 3819/3858 coupled to
  ensemble/benchmark state). Update importers: `auto-free.test.ts`, `free-only.test.ts`
  (point at the new module for the moved symbols). Guard: the existing tests.
- **Phase 2 — self-contained class.** Extract the AIMD `AdaptiveRateLimiter`
  (2677-2775) to `rate-limiter.ts`; index.ts keeps the singleton instance + wires
  `classifyError`/retry to it via the imported class. Add a unit test (it is
  deterministic). Then the rate-limited parallel executor (2776-2834).
- **Phase 3 — the dispatch cores (UNBLOCKS A6, highest risk).** Extract the
  `code_task` and `scan_folder` handler cores from the dispatch block into
  importable modules (mirror the A6 `runSearchExistingImplementations` extraction:
  inject the shared seams — fetch impl, model resolution, rate limiter — rather than
  reading module globals, so the core imports WITHOUT triggering `main()`). This is
  the gate for A6 (TRDD-828238b5 A6 free-form benchmarks). Do it in its own sub-phases
  per tool, each guarded by the full suite + a new in-process runner test.
- **Phase 4 — tool definitions.** Move `buildTools()` (3588-4919) + the scattered
  ensemble/free selection helpers (`selectFreeEnsembleModels`,
  `FREE_FLOOR_MIN_CONTEXT_TOKENS`) into `tools/definitions.ts`, keeping the dynamic
  description refresh (`refreshAllToolDescriptions`, `limitsBlock`) working. The
  `doc-consistency` gate guards the tool-count/name invariants.
- **Phase 5 — remaining completion/connection layers.** Streaming/JSON completion,
  connection setup, LM Studio API, retry-on-truncation — each its own phase with a
  context object for shared state, only after Phases 1-4 prove the pattern.

## Risk + acceptance

- Acceptance per phase: `npm run build` (tsc+esbuild) green, `npm test` (≥1133) green,
  `eslint --max-warnings 0` clean, `doc-consistency` green, dist rebuilt + committed.
- Roll back a phase with `git revert` if the suite goes red — never force a partial.
- Do NOT combine phases. Do NOT introduce re-export shims. Do NOT let an extracted
  module import back from index.ts.
