# Automatic fallback of general commands to a ready local profile on remote service failure

## Rationale (one sentence)

EHT of TRDD-UT7UC025: when the REMOTE SERVICE of the active free/paid profile fails (provider outage, no network, 402 credit exhaustion, a refused API key 401/403), a general command finishes on a READY local profile (locals-mlx or local_llama) instead of dying, never silently, never by starting a download or a calibration, and never for a failure that is about this one request or one dead model inside a healthy service. The 2026-11-13 USER goal is in the parent card verbatim; the 7 design constraints named below are the parent card own derivation of it (agent text, advisor-reviewed, NOT USER words). REVISION 2 (2026-11-13, after an adversarial review): scope now includes free-rotation, a third trigger independent of model count, per-walk deps instead of a latch read by globals, time bounds, tests, and section 8 split into agent decisions and open questions. Markers: [V] = VERIFIED, file:line read this session; [I] = INFERRED, must be read by the implementer before relying on it. All paths under scripts/llm-ext/src/.

   FREE-PATH EXITS of callWithFreeRotation and the typed-cause carry: moved to TRDD-3CG178O7 (1a).
NEVER falls back (existing verdict order kept, nothing new to maintain):
 - request-specific 4xx: every cause non-transient 4xx and at least one not service-level (NON_TRANSIENT_4XX_RE index.ts:2323, SERVICE_LEVEL_STATUS_RE index.ts:2321, branch index.ts:2379 [V]). ## 5. Mechanics

 - Reuse the --profile path: resolve the target with resolveProfile(name, activeSettings.profiles[name]) (config.ts:4262 [V]) and walk it with the SAME walkProfileChainOnce (index.ts:3414 [V]); managed models then go through localBroker (index.ts:1966 -> ensureBroker -> broker -> governor lease kind inference, broker/server.ts:1165 [survey, not re-read]). No spawn or lease code is added. The walk gets PER-WALK DEPS (built in TRDD-78LZFUVJ 1c), not the module globals.
 - BINDING problem, the activeResolved inventory and the DECISION option X (per-walk deps, makeProviderDeps): moved to TRDD-78LZFUVJ (1c); this card calls makeProviderDeps over the target profile and a backend built ONCE with makeBackendFromProfile.
 - Input budget, refuse never truncate (constraint 3): the remote args were sized at dispatch for the REMOTE profile (inventory item 6): per file up to 400 KB. At the fallback site compute the byte size of the messages and compare with the TARGET sizing, localSizingFor(target, tool) (local-input-budget.ts:180 planLocalSizing [V]): state must be calibrated (await or default means not ready, never wait), windowBudgetBytes bounds the request; over it = refuse THAT request with a message naming bytes, budget and model, and throw the ORIGINAL verdict; other files of the command continue (Q9). Clamp options.maxTokens to sizing.maxTokens (the remote value can be far above a local window). The tool name is read from ctxStore.getStore()?.tool (connection.ts:200 and index.ts:180 [V]); this function receives tool = default from all its callers [V], and taskEntryOf(default) is undefined, which makes planLocalSizing return null [V], so the ctxStore tool is required. MIN_LOCAL_INPUT_TOKENS = 1024 (local-input-budget.ts:35 [V]). CONSEQUENCE: with the 400 KB per-file default most real file requests will be refused by a small local window; the fallback mainly saves small requests (see section 7).
 - Latch per run (constraint 4): once the first fallback succeeded, later calls in the same command skip the remote attempt (it would burn the retry window per file) and go straight to the local walk. Scope the latch with ctxStore like localSizingMemo (WeakMap keyed by the command usage context, index.ts:205 [V]), not a process global. The latch is checked at the TOP of chatCompletionWithProfileFallback, callSingleWithFreeRotation and the JSON site; the ensemble sites (increment 2) do not read it, so an ensemble call in a latched command still tries the remote (known, section 7). Decision Q8: never retry the remote within one command.
 - Never silent (constraint 6): one stderr warning at the switch (remote verdict, target profile and model, degraded). Fixed texts (section 8): paid 402 = "credit exhausted on the paid profile: top up; answered locally"; refused key 401/403 = "the API key was refused (401/403): fix it; answered locally". ANSWERED-BY LABEL SOURCE [V]: StreamingResult.model (provider/types.ts:84-92) is data.model ?? options.model (completion.ts:735); it flows to the usage log (formatFooter, index.ts:2049) and to the report Model line (index.ts:2160), so the local model id already shows as the answerer. For an explicit marker add an optional StreamingResult field (fallbackFrom: the remote profile name) stamped by the helper and printed where meta.model is printed [I: how each tool builds meta was not traced].
 - --stop_on_errors (SWNIIFTF): stopIfStopOnErrors runs inside walkProfileChainOnce for every stop-worthy failure (404, 410, 402, 5xx, network, certain payment; provider/http.ts:620-638, call site index.ts:3478 [V]) BEFORE the catch that would start the fallback, and throws a stop (exit 6, command-stop.ts:18 [V]). So with the flag an outage or credit failure never reaches the fallback: no new code, only a test. 401/403 are not stop-worthy [V] and DO fall back (section 8, Q3 REVISED), so with the flag they still fall back. Low-memory waits in the broker queue are not failures and never trigger anything.
 - JSON sub-step (check_imports only): chatCompletionJSONWithFreeRotation returns JSONCompletionResult, not StreamingResult, and walkProfileChainOnce returns StreamingResult, so the helper takes a run callback and the JSON site passes one that loops the target chain calling chatCompletionJSON with the per-walk deps (chatCompletionJSON takes deps as its third argument, index.ts:3379 [V]). Whether chatCompletionJSON honours options.route is NOT read [I]; if it cannot take a route, the JSON site moves to increment 3 and this card is amended, the other two sites unaffected.

## 7. Risks

 - Governor contention with the mlx-decision decider (parent Open questions [V]): fallback llama/Locals jobs hold governor inference leases exactly when remote models are down, which is when classify escalates to the decider, whose lease is fast-failed after 60 s (O93LFMF3, local-fallback.ts:196 takeDirectLease [survey]). Increment 1 makes this routine. Needs a decision (reserved slot or priority for the decider) before or with this increment. See question 4.
 - RAM and CPU: loads are admitted by the governor against the RAM limit and wait rather than fail (survey, controller.ts); a first-use load of a 3-15 GB model during an outage can look like a hang for minutes. --command_timeout and --queue_timeout still bound it (survey [V cards]).
 - First-use calibration must never run on the failure path: guarded by section 4 plus the noHold gap.
 - A latched run keeps hammering the local model for every remaining file; the broker one-model-type-at-a-time rule and queue limit modulate it, but quality is degraded and the USER sees it only through the one warning and labels.
 - Two partitions of causes drifting apart: avoided by extracting the shared predicate.
 - INPUT BUDGET REFUSALS: dispatch sizes input for the remote profile (400 KB per file default), so on a small local window most real file requests are refused (section 5); the fallback mostly saves small requests (chat, classify-sized, short files). The single warning should say how many requests were refused.
 - Network blip, give-up window and blackhole risks: moved to TRDD-PN0N4290 (1b).
 - Free path before the typed-cause carry (only trigger c): moved to TRDD-3CG178O7 (1a).
 - Concurrency after a latch: the per-file pool stays sized for the remote profile (up to 200 in flight, index.ts:696 [V]); the broker queue absorbs it but time and memory pressure rise (TRDD-78LZFUVJ inventory item 5).
Cross-ref: governor slot priority for the mlx-decision decider is USER Q4; the O93LFMF3 lease fast-fail memo is provisional until it is answered.
