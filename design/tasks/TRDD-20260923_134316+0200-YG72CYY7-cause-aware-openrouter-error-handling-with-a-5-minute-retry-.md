## Plan (increments; each one type-checked, linted, tested and committed before the next)
1. Retry clock: optional `deadlineAt` on SimpleCompletionOptions, defaulted in chatCompletionWithRetry at the first failure (RETRY_DEADLINE_MS = 300000, independent of settings.yaml timeout). It gates only the start of a new attempt or wait, and never aborts an in-flight request. The HTTP retry ladder (fetchWithRetry429), the empty-reply retries and checkServiceHealthOrWait check it. The breaker never waits past it and never claims a ladder slot without time left. When the clock runs out, a RetryDeadlineError is thrown with a neutral message (no transient vocabulary) and a trail {attempts, elapsedMs, lastStatus, lastProvider}; the last error goes in `.cause`. classifyError treats it as final for the file. The attempt counters and RUN_PAID_EMPTY_RETRY_BUDGET stay as spend guards. Test: a real node:http server returning 503, with a 4 s deadline.
2. One shared clock per dispatcher scope (ensembleStreaming, chatCompletionWithProfileFallback, callSingleWithFreeRotation, chatCompletionJSONWithFreeRotation). callWithFreeRotation and walkProfileChainOnce check it before the next candidate, with no recordUnavailable for untried models.
3. Typed failure fields on the thrown error (status, OpenRouter error code, metadata.provider_name, metadata.raw, and the network code unwrapped from undici `fetch failed` / AggregateError); the message stays byte-identical. A new classifyFailure(err) reads them:
   - ECONNREFUSED gets a short budget (2 tries), then stops with the cause named; ENOTFOUND/EAI_AGAIN for the OpenRouter host get the full window (see Revisions after review);
   - ECONNRESET/ETIMEDOUT/UND_ERR_*/socket hang up get the full window;
   - TLS certificate errors stop;
   - 504 gets at most 2 retries, then a hint that the prompt is too large or slow for the model;
   - 408 is added to the retryable statuses.
   Kept unchanged: classifyUnavailable (daily-quota rotation until UTC midnight), the 402 certain/uncertain handling (TRDD-OE27RD7I addendum 4: no switch to free models). provider_name is recorded in the per-model event ledger detail.
4. Provider state: getModelSupportedParams keeps the full /models/{id}/endpoints array (status, uptime_last_30m, provider_name) instead of only supported_parameters. A give-up on a provider-side cause then reports "N of M providers degraded" with names and uptime.
5. Deferred: client-side provider.ignore. Only if the ledger shows repeat same-provider 5xx within one call, and only on the OpenRouter backend, never with allow_fallbacks=false, never a provider named in `order`, and never emptying the eligible set.

## Out of scope

## Revisions after review (2026-09-23)

- Clock start: one shared clock object per dispatcher scope; it starts at the FIRST FAILURE in that scope, not at entry. Increments 1 and 2 use this same definition.
- DNS and connection causes: ENOTFOUND/EAI_AGAIN for the OpenRouter host count as `network` and get the full 5-minute window (laptop sleep, Wi-Fi change or VPN blips are transient). Only ECONNREFUSED (nothing listening, e.g. a local runner not started) gets the short budget of 2 tries. This follows the adversarial review and overrides the advisor's short budget for ENOTFOUND.
- Increment 4 (provider status in the final error) is kept, although the advisor advised deferring it, because the USER explicitly asked to use OpenRouter's model and provider state APIs. It runs on the OpenRouter backend only; b.ai and local backends skip it.
- session_summary gets a shorter retry window, so a chunk's latency stays below its caller's timeout (the session-summary convergence contract).
- When Retry-After exceeds the remaining window, stop at once with cause rate-limit and say when to retry.
- Test fixtures come from real recorded error bodies (the per-model event ledger and past reports) as well as the OpenRouter documentation examples.
