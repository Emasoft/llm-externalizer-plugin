# Local decider fallback that starts or adopts a loopback mlx-decision server

Increment 1 of the local fallback tier of TRDD-UT7UC025 (an EHT of that card): a decision can still be classified when no remote System One model is available.

The staged diff adds and removes no governor line.

Increment 2 (historical, superseded by the 2026-11-13 STATE: built as C1-C4). The items below are unapproved candidate scope, not planned work: the wiring into run-decision and ping, the systemone-local endpoint producer, enforcement of local_fallback.enabled, a stop/lease path for the detached server, and decider identity on adoption. Also carried from the 7f6ac13b reviews, since validation cannot close it: local-transport.ts builds its endpoint as `${baseUrl.replace(/\/+$/,"")}/v1/systemone`, so a url carrying a query or a fragment mis-joins (a query swallows the path; a fragment is dropped), and a url whose path already ends in /v1/systemone gets the segment twice. All three parse to a loopback host, so none is a security escape — each is a correctness bug for the increment-2 wiring to settle, either by rejecting path/query/fragment at validation or by joining through new URL(). Those two remedies are NOT symmetric and they do not cost the same: rejecting at validation means changing isLoopbackDeciderUrl so it refuses a trailing slash, which the current check accepts, and which a trailing-slash url works with today (the sender strips it with replace(/\/+$/,"")) — no test pins that acceptance and no decision record claims it is intentional, so it is a behavior to preserve or change deliberately, not a decision already taken; joining through new URL() with an ABSOLUTE path (new URL("/v1/systemone", base)) fixes all three, measured: it discards the base path, so the doubled segment cannot occur, and it drops a base query and fragment. Only a RELATIVE join (new URL("v1/systemone", base)) doubles the segment (it yields /v1/v1/systemone), and no one is likely to write that. So the asymmetry is real but one-sided: rejecting narrows what a FUTURE config could write (this section has never shipped in a tag and no code path reads it, so no existing url is affected), while the absolute-path join costs nothing and needs no new validation, since this section already guarantees the base authority is loopback. The fragment case remains the weakest of the three for a different reason: it is safe because fetch does not transmit fragments, a property of the HTTP client rather than of the concatenation.

Port collision, stated as a fact: the increment-1 test fixture defaults to http://127.0.0.1:57455, and sibling card J7AIC7ZW (the OTHER local tier, Krill/Nanbeige 3B) records Krill serving on that same 127.0.0.1:57455. The two must not both claim it, and which port this one takes is an increment-2 decision, not settled here.
