## Cost-safety (hard invariant)

Zero OpenRouter spend. The harness MUST default to offline / `$0` checks. The only
network it may touch by default is the **public OpenRouter model catalog** (no key)
and `discover` (balance probe, no LLM). LLM-calling smokes are **opt-in** behind
`DOGFOOD_LIVE=1` and run ONLY through the validated free pool (auto-free or a
`free_only` profile) so a live smoke is still `$0`.

## Design — `dogfood-test` skill = a permanent harness

### The skill
- `skills/dogfood-test/SKILL.md`, frontmatter `name: dogfood-test`,
  `user-invocable: false` (maintainer/internal — never a slash command). Body
  documents how to run the harness, the cost-safety contract, and how to read the
  result table.
- No `commands/` wrapper (that is what makes it non-user-invocable).

### The harness — `tests/dogfood/dogfood_test.py` (run with `uv run`)
Repeatable, exit-0-on-all-pass / non-zero-on-any-fail. Phases:

1. **Build** — `npm run build` (or assert dist present + current). Fail → stop.
2. **Health (`$0`)** — `node bin/llm-ext discover`; assert auth resolved + a
   profile + status line; record auto-free state.
3. **CLI `--help` (`$0`, offline)** — for EVERY verb in TOOL_CATALOG:
   `node bin/llm-ext --help <verb>` → exit 0 + non-empty + has a "Parameters"/
   "Usage" section. Plus top-level `--help`, and `bin/llm-ext-benchmark --help`.
4. **Benchmark dry-run (`$0`)** — `llm-ext-benchmark --dry-run` (roster prints, no
   calls); `--bench-free-pool --dry-run` (free pool roster; refuses non-`:free`).
5. **Read-only `$0` tools** — `get_settings` (returns a path), `or_model_info_json`
   on one known model (public catalog), `discover-new-models` (catalog diff, no key).
6. **Slash-command structural audit** — every `commands/*.md`: frontmatter has
   `name`/`description`/`allowed-tools`; the wrapped tool name resolves to a real
   MCP tool / CLI verb. (Reuses the existing doc-consistency invariants.)
7. **Skill structural audit** — every `skills/*/SKILL.md`: valid frontmatter
   (`name`, `description`, `user-invocable` boolean).
8. **Opt-in FREE live smoke (`DOGFOOD_LIVE=1`)** — `chat` + `code_task` on a tiny
   fixture; assert exit 0 + a report file written + the model used ends in `:free`
   (so spend is `$0`). Skipped by default (free tier is heavily rate-limited).
9. **Report** — a Unicode-bordered result table (surface · name · status ·
   description) to stdout, and a full markdown report under
   `$MAIN_ROOT/reports/dogfood/<ts±tz>-dogfood.md`. Snail-mark slow/live rows.

A `tests/dogfood/README.md` documents invocation.

## Evaluate-and-fix

1. Run the harness → collect FAIL / WARN rows + (if run) the live-smoke evaluation.
2. For each discovered issue: triage real vs environmental (rate-limit ≠ bug).
3. **Fixing phase uses a Workflow** (user directive): fan out one fixer per real
   issue, each verifies its fix (build + lint + the harness row goes green),
   returns a structured verdict; orchestrator commits per logical group. No push.
4. Re-run the harness until all rows are PASS/skip. Wire the harness into the
   plugin's own `tests/` runner so it stays green on every future publish.

## Acceptance criteria

- [ ] `skills/dogfood-test/SKILL.md` exists, `user-invocable: false`, no slash wrapper.
- [ ] `tests/dogfood/dogfood_test.py` runs `$0` by default, exits non-zero on any FAIL,
      prints the Unicode result table, writes a report under `reports/dogfood/`.
- [ ] Every CLI verb, benchmark, slash command, and skill has a dogfood row.
- [ ] All discovered real issues fixed (via workflow) + harness fully green.
- [ ] build + lint + full vitest suite still green; no push.
