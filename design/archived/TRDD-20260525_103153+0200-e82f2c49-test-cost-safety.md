# TRDD-e82f2c49 — Test cost-safety (zero-dime default test/publish gate)

**Filename:** `design/tasks/TRDD-20260525_103153+0200-e82f2c49-test-cost-safety.md`
**Tracked in:** this repo (design/tasks/ is git-tracked)

## Incident

User's OpenRouter balance drained to $0. Root cause established on real ground:

- The active profile `remote-ensemble-geminigrok` runs **`deepseek/deepseek-v4-pro`
  in ensemble mode (3 models/call)** — a premium remote backend.
- `mcp-server/src/test-helpers.ts::createTestClient` **copies the real
  settings.yaml** into the spawned server's tmp config dir (comment: "so the
  server still resolves the real backend the tests depend on"), so
  `index.test.ts` — which runs on EVERY `npm test` and makes **23 real, ungated
  tool calls** (chat/code_task/...) — hit the premium ensemble for real.
- `security_scan_live.test.ts` runs on every `npm test` whenever
  `OPENROUTER_API_KEY` is set (gated on HAS_KEY only).
- Repeated `npm test` runs (≈8–10 this session, for verification) therefore made
  hundreds of real premium calls. The local ledger `~/.llm-externalizer/history.log`
  did NOT show it because the test server logs to a throwaway tmp config dir —
  so the ledger read ~$0.12 while the real balance drained.

`index.test.ts` was DESIGNED to need no paid backend (docstring: calls should
"fail before/after the LLM call … connection refused to localhost:1234"). The
test-helpers drift to the real remote backend is the defect.

## Hard success criterion

`npm test` (and `publish.py` G4, which runs `npm test`) makes **ZERO** OpenRouter
calls. Real-LLM tests run ONLY under an explicit opt-in (`LIVE_TESTS=1`).
Verified WITHOUT spending (offline unit tests + confirming the live/integration
suites skip / fail-free; never re-run a real-LLM path).

## Changes

1. **`test-helpers.ts` — default to a LOCAL, unreachable backend (free).**
   - `resolveTestConfig({ testName, timeout?, requireLiveBackend? })`. Default
     (`requireLiveBackend` falsy) returns a synthetic LOCAL profile
     (`mode: local`, `api: generic-local`, `url: http://127.0.0.1:1` — a
     guaranteed-dead port). A local profile NEVER contacts openrouter.ai (local
     mode → local URL), so no call can bill, regardless of the user's real
     config. `requireLiveBackend: true` keeps the current behavior (read real
     settings + active profile) for the deliberately-LIVE suites.
   - `createTestClient` writes the synthetic local settings.yaml into the tmp
     config dir by default; copies the real settings.yaml only when
     `liveBackend` is set on the config.
   - index.test.ts's plumbing/validation/progress/answer_mode tests then run
     as DESIGNED (calls fail-fast on ECONNREFUSED — free) — full coverage kept,
     zero spend.
2. **`security_scan_live.test.ts` — require `LIVE_TESTS=1`** (not just HAS_KEY),
   matching the other live suites.
3. **`live.test.ts` / `live-extended.test.ts`** — pass `requireLiveBackend: true`
   (they genuinely need a real backend; they are NOT in the default vitest
   include and are LIVE-gated).
4. **Regression guard** — a new offline unit test asserting
   `resolveTestConfig()` default resolves to `mode: local` + a non-openrouter
   url, so a future revert to the real backend fails a FREE test.
5. **Docs** — `tests/README.md` (or create) documents: default `npm test` is
   offline + free; real calls require `LIVE_TESTS=1` and cost money.

## Out of scope / follow-up
- A3's catalog-preferred `maxOutput` only matters when a real call is made; with
  the default gate offline it can't auto-spend. Optional cap is a separate item.
- Pointing the LIVE integration tests at a CHEAP model (vs the user's active
  premium) is a further safety improvement — separate follow-up.

## Verification (no spend)
- `npm test` → index.test.ts real-call tests pass via ECONNREFUSED (no
  openrouter contact); security_scan_live + live suites SKIP; all unit tests
  green; NO `backend: OpenRouter (deepseek...)` real-call banner, no multi-second
  real durations. `tsc` + eslint clean.

## Additional change shipped (not in the original list)

6. **`index.ts` entry-point guard.** `default-output-dir.test.ts` does
   `await import("./index.js")` to reach `_testDefaultOutputDir`, which ran
   index.ts's top-level `main()` → booted the server against the REAL backend
   (free metadata only, but a flaw). Wrapped `main().catch(...)` in an
   `__isEntrypoint` check (`realpathSync(process.argv[1]) ===
   realpathSync(fileUrlToPath(import.meta.url))`). The spawned
   `node dist/index.js` MCP server still boots (argv[1] matches); importing the
   module never does. Consistent with the existing line-9441
   `fileUrlToPath_cs(import.meta.url)` usage; esbuild ESM output preserves
   `import.meta.url`.

## Outcome — CONFIRMED by OpenRouter activity export

User downloaded the real OpenRouter activity logs
(`docs_dev/openrouter-logs/`). They confirm the diagnosis exactly:

- **$26.46 total** over ~2 days; **$17.67 (67%) in the single 08:00 hour** I
  ran `npm test` ~10×.
- **244 ensemble ops in that hour** (deepseek-v4-pro + gpt-5.4-nano +
  gemini-3.1-flash-lite-preview), 244 / 23 ≈ 10.6 runs — matches.
- Cost driver = **reasoning tokens**: gemini-flash-lite emitted 6.5M reasoning
  tokens in that hour → $10.44 alone.
- **No hidden auto-spend** anywhere else: server boot, `discover`,
  `check_model_health`/drift (A2), `discover_new_models`/new-arrivals (A4) all
  use the FREE `/v1/models` catalog endpoint only; the only `setInterval`s are
  in-flight progress timers, not billed background loops.

Post-fix full-suite run (no API key): 887 passed / 4 skipped; every
spawned-server boot line is `Local (http://127.0.0.1:1, test-model)`; ZERO
`OpenRouter (deepseek...)` lines. `npm test` now bills $0.00.
