## Servers (revision 3, after the two-servers rule and the user's 2026-10-28 answers)
- Server-count safeguard (user rule 2026-10-28): per local inference engine llm-ext runs at most one main server and one benchmarking/testing (calibration) server at any time and refuses to spawn any other. Exception ruled by the user: Locals serves one model per server, so locals-mlx runs one main Locals server per profile model (three) plus one calibration server. The safeguard counts llm-ext's own state files per engine under one lock and refuses a spawn above the limit with a clear error.
- local_llama (llama.cpp): ONE main server in router mode (`llama-server --models-preset <ini> --models-max 3 --host 127.0.0.1 --port 8181`), the preset written by llm-ext with one section per model (LFM3 AD-Q6_K, Nanbeige4.2 Q6_K, Qwen3.5 Q8_0 by absolute cached file path or HF id) and a ctx-size per model; requests select the model by its preset id. Measured: all three loaded at once, about 12.3 GB, per-model ctx works, internal child processes per model (counted as one server, user ruling). The router has no API key and open CORS (2c later).
- locals-mlx (Locals): 9090 LiquidAI/LFM3-1.7B-MLX-4bit; 9091 mlx-community/Nanbeige4.2-3B-OptiQ-4bit; 9092 mlx-community/Qwen3.5-4B-MLX-4bit, each `python -m locals.server` with --slots, --max-context and --cache-gb set.
- Calibration: one separate calibration server per engine on a private port, controlled freely by calibration (user ruling 2026-10-28); user-facing servers keep refuse-on-change.
- Every server starts with an explicit context (provisional until calibration, then the calibrated ceiling); the reading of "reduced context memory": a smaller server context and a smaller per-request share for mass-scouting. Memory table from P0. The 2-hour idle kill (2e) covers every server; server-status lists them all.
